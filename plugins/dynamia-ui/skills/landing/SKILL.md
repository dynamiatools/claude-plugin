# dynamia-ui:landing

1. **Know the page's one job** (sign up, book a demo, buy, install) and the visitor (who, what they already know). Ask only what you cannot see in the repo or the brief.
2. **Pick the pattern** for the product type from `references/patterns.md`, adapt the section order, then write the structure as a short outline with the headline and the call to action for each section.
3. **Build or review** with the project's stack and `design-system/MASTER.md` tokens. For a review report `file:line`, problem, fix, most severe first; change code only after approval.
4. **Check the page** with `dynamia-ui:ux-review` (mobile first), `dynamia-ui:seo-review` and `dynamia-ui:perf-review`.

Do not invent customers, numbers, logos, testimonials or awards. Use placeholders marked `TODO` and say which facts the user must supply. End with one line: what was built or reviewed, what the user must supply, any risk left.
